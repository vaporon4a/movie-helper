# Короткие анонсы для участников

Заметная пользователям фича получает отдельный UTF-8 файл `<уникальный-id>.txt`.
Технические правки могут обходиться без файла. Один файл — один абзац или несколько
коротких пунктов о пользе и новых командах, до 1500 символов. Обычный текст,
без Markdown/HTML. Например:

```text
• Теперь можно предлагать идеи через /idea.
• Полные описания доступны кнопкой под голосованием.
```

Файлы проверяются вместе с кодом в PR и накапливаются до успешного деплоя. При настроенном канале после него автоматически публикуется одна сводка.
Не добавляйте обещания ещё не реализованных возможностей. Новые команды проверяйте
в тестовой группе перед анонсом. В описании PR пишите «Анонс: <id>» или
«Без анонса: внутреннее изменение».

Деплой сохраняет весь каталог в релизе сервера. Workflow `Retry or preview bot announcement`
читает именно этот каталог и проверяет, что выбранный SHA сейчас запущен и прошёл
readiness. Поэтому анонс нельзя отправить для ещё не установленного коммита.

1. Анонсы отправляются автоматически во все группы из `ALLOWED_CHAT_IDS`
   активного релиза сервера. Отдельная переменная и кнопка не нужны.
   Бот должен иметь право отправлять сообщения в этих группах.
   `bootstrap` не имеет адресатов, отправка пропускается.
2. Проверяйте фичу и текст анонса до merge/push в main. После успешного деплоя
   все ещё не опубликованные записи отправляются каждой подключённой группе.
3. Ручной **Retry or preview bot announcement** остаётся для предпросмотра
   (`publish=false`) и повторной отправки после явного отказа (`publish=true`).
   Запускайте для main на текущем установленном SHA. Повторите только failed job
   анонса/ручной workflow; не перезапускайте деплой ради доставки сообщения.
4. Общая сводка ограничена 3500 символами; большой текст не разбивается
   автоматически и требует сокращения непубликовавшихся записей.

Дедупликация хранится на сервере в `/opt/movie-helper/announcement-ledger.json`,
отдельно для каждого канала. Успешно опубликованные ID больше не отправляются.
Не изменяйте опубликованные записи: для уточнения создайте новый ID.
Смена ID старого текста приведёт к новой публикации. Не удаляйте старые записи
из ledger; сохраняйте этот файл при переносе сервера.

При явном отказе Telegram (включая 429) можно повторить только announcement workflow.
Автоматических повторов нет. При тайм-ауте, сбое сети или прерывании после начала
отправки записи остаются `unknown`: повторный запуск блокируется, чтобы не создать
дубль. Проверив канал, оператор под блокировкой `/opt/movie-helper/deploy.lock`
в ledger меняет `state` всех записей данного сообщения на `sent`, если сообщение
есть, либо удаляет эти записи, если подтверждено отсутствие доставки. При
неуверенности оставляет `unknown`. Токен бота берётся из активного `runtime.env`
и не передаётся в аргументах SSH или логи.

Повторный деплой не сбрасывает историю анонсов. Деплой и публикация используют
общую блокировку на сервере и общую concurrency group в Actions.
Сбой анонса не вызывает повторный деплой. Для первого использования необходим
новый успешный деплой с `ready.json` и каталогом анонсов; прежние релизы не подходят.
