# Movie Helper

Telegram-бот для дружеского киноклуба. В v0.1 — **мем дня и факт о кино**, очередь предложений, одобрение администраторами и расписание для каждого чата. Выбор фильмов, голосования и приватный рейтинг — следующие этапы.

Go 1.27.1, `go-telegram/bot`, SQLite с миграциями Goose, один процесс long polling. Docker Compose хранит данные в volume; домен и входящие порты не нужны.

## Запуск

1. Создайте бота через [BotFather](https://t.me/BotFather), добавьте в группу и разрешите отправлять текст и фотографии. Выдавать административные права самому боту не требуется. Команды адресуйте `/help@имя_бота`, особенно при включённом Privacy Mode.
2. Подготовьте конфигурацию:

   ```sh
   cp .env.example .env
   chmod 600 .env
   ```

   В `.env` заполните `BOT_TOKEN`, `ALLOWED_CHAT_IDS` (отрицательные ID групп через запятую) и, для отбора картинок и автоматических фактов, `GEMINI_API_KEY`. Реальные ключи не добавляйте в Git. Для первого определения ID можно оставить пример разрешённого чата, запустить бота и отправить `/id@имя_бота` в нужной группе: эта команда работает вне списка. Затем обновите `.env` и пересоздайте контейнер.
3. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs --tail=100 -f bot
   ```

4. Администратор группы явно включает рубрики:

   ```text
   /timezone@имя_бота Europe/Moscow
   /schedule@имя_бота meme 09:00
   /schedule@имя_бота fact 12:00
   /settings@имя_бота
   ```

Рассылка изначально выключена. Время относится к часовому поясу чата. Если сегодняшнее время уже наступило, первое сообщение будет завтра. `/pause meme` и `/pause fact` выключают соответствующую рубрику. Изменения `.env` применяются через `docker compose up -d --force-recreate`, а не `restart`.

Один токен обслуживает один процесс. Активный webhook препятствует запуску; приложение не удаляет его автоматически. Второй процесс с той же БД блокируется файловой блокировкой. SQLite рассчитана на локальный Docker volume одного сервера.

## Откуда берутся материалы

**Одобренная очередь всегда имеет приоритет.** Если она пуста, бот получает внешние материалы:

- Мемы: [Meme API](https://github.com/D3vd/Meme_Api), по умолчанию `RUSSIANMemeSub`. До 10 кандидатов на subreddit, фильтры NSFW/спойлеров, русскоязычного заголовка и формата JPG/PNG с `i.redd.it`. Gemini просматривает до четырёх картинок и выбирает одну либо отказывается. Публикуется оригинальная картинка со ссылкой на пост. Это общий русскоязычный юмор; наличие киношных мемов и качество не гарантированы. `MEME_SUBREDDITS` позволяет задать до пяти источников через запятую.
- Факты: разделы Production/Development/Filming английской Wikipedia через [MediaWiki TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts). Gemini готовит до 40 слов по-русски и возвращает подтверждающую цитату, наличие которой проверяет код. Ссылка берётся из ответа Wikipedia, привязана к редакции статьи; добавлены атрибуция, отметка переработки и [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Такая проверка уменьшает выдумки, но не доказывает истинность текста модели или самой статьи.

Стартовый список содержит 20 фильмов. На одну попытку получения факта читается до трёх ещё не использованных статей; порядок меняется по UTC-дню. **Один автоматический факт на название статьи в каждом чате.** При исчерпании списка пополните `FACT_WIKI_TITLES` английскими заголовками статей, разделёнными `|` (до 100), например:

```dotenv
FACT_WIKI_TITLES='Alien (film)|The Matrix|Jurassic Park (film)'
```

Это начальный ограниченный каталог, а не бесконечный поиск по интернету. Пустой `FACT_WIKI_TITLES` включает встроенный список. Статьи без подходящего раздела пропускаются. Переписка участников, их имена и ручная очередь в Gemini не передаются: только общедоступные картинки, заголовки и фрагменты статей.

Без `GEMINI_API_KEY` мем выбирается по популярности после базовых фильтров, без визуальной оценки; факты доступны только из ручной очереди. При подключённом Gemini его ошибка, отказ или исчерпание лимита не обходятся публикацией неотобранного мема. Если подходящего материала нет, слот пропускается без сообщения в чат. Следующая автоматическая попытка — в следующий дневной слот; ручную очередь можно пополнять заранее.

### Gemini

Ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey). Модель задаётся `GEMINI_MODEL`, по умолчанию `gemini-2.5-flash`; используется REST `generateContent` со структурированным JSON-ответом. Выбранная замена должна поддерживать изображения и JSON Schema.

`GEMINI_DAILY_REQUEST_LIMIT=6` — общий предел **попыток** обращения ко всем чатам за UTC-сутки. Счётчик хранится в SQLite и переживает перезапуск; ошибки тоже расходуют попытку. `0` блокирует вызовы модели. Для одного чата с двумя рубриками обычно нужно до двух вызовов в день. Это ограничение числа запросов, а не бюджета в деньгах: проверьте [тариф модели](https://ai.google.dev/gemini-api/docs/pricing), [квоты проекта](https://ai.google.dev/gemini-api/docs/rate-limits), [доступность региона](https://ai.google.dev/gemini-api/docs/available-regions) и [условия обработки данных](https://ai.google.dev/gemini-api/terms).

Встроенный Google Search grounding не используется. Независимые источники позволяют сохранять очередь и публиковать её по расписанию без привязки к поисковому ответу конкретному пользователю.

## Очередь и права

- Участник отвечает `/suggest_meme@имя_бота` на одну фотографию, не альбом. Бот сохраняет Telegram `file_id`, без скачивания файла. С Privacy Mode надёжнее адресовать команду явно.
- `/suggest_fact Текст факта | https://источник` добавляет предложение с текстом до 1500 символов.
- Администратор открывает `/queue`, затем `/review ID` и нажимает «Одобрить» или «Убрать». Есть команды `/approve ID` и `/reject ID`. Для следующей страницы: `/queue последний_ID`.
- Ручное предложение публикуется только после одобрения. Автоматически отобранные внешние материалы публикуются без отдельного одобрения.
- Изменять расписание и очередь могут владельцы и администраторы текущей группы, проверяемые через Telegram. Анонимные команды от имени чата не принимаются. При ошибке проверки права не предоставляются.
- Материалы, история повторов и настройки изолированы по `chat_id`; ID материала чужого чата не даёт к нему доступ. Эти данные доступны участникам своей группы и оператору сервера, а не являются зашифрованным хранилищем.

## Доставка и восстановление

Проверка расписания идёт каждые 15 секунд. Один слот каждой рубрики на локальную дату; окно отправки — 60 минут. При долгом простое старые публикации не догоняются. При смене времени или часового пояса ожидающие доставки отменяются, материал возвращается в очередь. Уже отправляемый сетевой запрос может завершиться.

После подтверждённого Telegram `429` учитывается `retry_after` в пределах окна. При потере доступа к чату рассылка выключается: восстановите права, выполните `/resume` и снова `/schedule`. Преобразование группы в supergroup требует нового `ALLOWED_CHAT_IDS` и настройки в новом чате; старая история сохраняется под старым ID и автоматически не переносится.

Telegram и SQLite не имеют общей транзакции. После таймаута или падения между отправкой и записью результата доставка становится `unknown` и автоматически не повторяется. `/settings` показывает последние неопределённые и ошибочные доставки. Проверьте чат и выполните `/resolve ID sent`, если пост появился, либо `/resolve ID requeue`, чтобы вернуть материал в очередь **следующего доступного дня**. Во втором случае возможен повтор. Строгая exactly-once доставка не обещается.

Логи содержат тип события и технические ID, без токенов, текста переписки и ответов внешних API. Недоступность источника видна в логах. Ошибочные материалы не повторяются бесконечно.

## Обновление, CI и резервные копии

Workflow проверяет форматирование, `go vet`, тесты с race, Compose и Docker build. После успешных проверок push в `main` или тега `v*` публикует `ghcr.io/vaporon4a/movie-helper:sha-<полный commit SHA>`. PR образ не публикует. Автоматического деплоя на сервер нет; публикация требует разрешения GitHub Packages для репозитория. Для приватного GHCR серверу нужен отдельный вход с правом чтения пакета.

Для готового образа задайте `BOT_IMAGE` в `.env`, затем:

```sh
docker compose pull bot
docker compose up -d --no-build
```

Перед обновлениями сохраняйте volume с остановленным ботом. Пример согласованной копии (архив включает БД и возможные WAL-файлы):

```sh
docker compose stop bot
mkdir -p backups
bot_volume=$(docker inspect --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}' "$(docker compose ps -aq bot)")
bot_backup="movie-helper-$(date -u +%Y%m%dT%H%M%SZ).tgz"
docker run --rm --mount "source=$bot_volume,target=/data,readonly" \
  --mount "type=bind,src=$PWD/backups,target=/backup" alpine:3.23 \
  tar czf "/backup/$bot_backup" -C /data .
docker compose start bot
```

Скопируйте архив во внешнее место; `.env` храните отдельно. Для восстановления остановите бота, распакуйте архив в **новый пустой volume**, сохраните владельца `65532:65532` и подключите его вместо `bot-data`. Проверьте `/settings` и `/queue`, прежде чем включать рассылку. Не копируйте отдельный файл работающей SQLite и не используйте `docker compose down -v`: он удаляет данные. Откат приложения с несовместимой схемой требует совместимой резервной копии; автоматического Down при запуске нет.

## Разработка

```sh
go test -race ./...
go vet ./...
docker build -t movie-helper:local .
```

Для `go run ./cmd/bot` переменные окружения задаются в оболочке; `.env` читается Docker Compose, само приложение файл не загружает. Локальная БД по умолчанию `data/movie-helper.db`, путь меняется через `DB_PATH`. Целевая ОС — Linux (файловая блокировка `flock`).

Пакеты: `config` — конфигурация; `telegram` — команды и доставка; `daily` — общие типы; `storage` — SQL и миграции; `scheduler` — расписание; `content` — выбор источника; `meme` и `gemini` — внешние адаптеры. Сборка зависимостей в `cmd/bot`. Будущие фильмы, встречи, опросы и рейтинг можно добавлять отдельными пакетами и миграциями.

Тесты используют реальные временные SQLite и подменённые HTTP/Telegram, проверяют изоляцию, права, повторы, перезапуск, DST, ошибки доставки, источники и предел Gemini. Для проверки настоящей интеграции нужны отдельный Telegram-токен, тестовая группа и Gemini-ключ: проверить `/id`, административные команды, фото по `file_id`, обе рубрики и сохранение очереди после пересоздания контейнера.
