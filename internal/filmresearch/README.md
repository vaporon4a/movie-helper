# Адресные опросы после просмотра

Функция реализована за переключателем `FILM_RESEARCH_MODE=off` по умолчанию.
`shadow` готовит наборы, но оставляет шаблонные опросы. `on` разрешает использовать
проверенный набор при первом резервировании. `FILM_RESEARCH_CHAT_IDS` ограничивает
пилот подмножеством `ALLOWED_CHAT_IDS`; пустое значение означает все разрешённые чаты.
Изменение режима относится к новым просмотрам. Существующие серии не переписываются.

## Путь данных

1. `/movie_watched` сохраняет просмотр и его ревизию. Участники равны.
2. Фоновая очередь готовит первые две подходящие FIFO-сессии чата, ниже приоритета
   пополнения ежедневных рубрик. Подготовка не создаёт сообщений в Telegram.
3. TMDB устанавливает ID/год, даёт русское описание и до двух отзывов. Wikipedia
   используется только после проверки cross-ID Wikidata/TMDB/IMDb, названия и года,
   с фиксацией revision. Берутся первые два абзаца сюжета и до двух абзацев критики.
   Отзывы сохраняются как `opinion`, а не как установленный факт. Досье ограничено
   18 КБ текста; недостающие сведения не дополняются из памяти модели.
4. Генератор предлагает четыре вопроса по разным предметам. Семейства сравнения,
   определения и шкалы заданы приложением. В запросе источники имеют короткие
   ссылки `s1`, `s2`; перед сохранением они заменяются точными SHA-256 ID.
5. Код проверяет контракт, ссылки, длины, разные цели и очевидную подмену шкалы.
   Отдельный AI-запрос проверяет основание, нейтральность, один предмет измерения,
   спойлеры и понятность каждого вопроса. Проверяющая модель обязана привести дословную
   цитату из выбранного фрагмента и объяснить соответствие предмету измерения; код
   проверяет принадлежность цитаты именно указанному фрагменту. Это необходимое,
   но не достаточное доказательство смысла. Допустима одна попытка исправления набора.
   Неодобренный набор не поступает в расписание. AI-проверка не гарантирует отсутствие
   всех смысловых ошибок: редакторская проверка пилота остаётся необходимой.
6. Этапы `sources → generate → audit → ready` сохраняются в SQLite; повторный запуск
   продолжает с контрольной точки. Один шаг ограничен 110 секундами при lease 6 минут.
   Долгий Retry-After сохраняется в фоновой очереди, ожидание не держит executor.
   `FILM_RESEARCH_GEMINI_MODEL` (по умолчанию `gemini-3.5-flash-lite`) приоритетен; после двух отложенных ошибок используется `FILM_RESEARCH_GROQ_MODEL` (по умолчанию `openai/gpt-oss-120b`). Это отдельные настройки адресных опросов, модели остальных функций не меняются. Исчерпание
   локального лимита Gemini позволяет попробовать Groq. Параметры для этой функции: temperature=0.3, Groq reasoning=low для GPT-OSS, до 4096 output tokens; они записываются в provenance. Бюджеты общие с ботом,
   каждый HTTP-запрос, включая проверку, учитывается. После 16 шагов — отказ подготовки.
7. При первом резервировании план и первые дочерние вопросы фиксируются одной
   транзакцией. Если проверенного набора нет, целиком используется прежняя v1-серия.
   Поздний AI не меняет `planned`, `creating`, `unknown` или уже опубликованные вопросы.
8. Общая оценка остаётся прежней. Дополнительно — четыре адресные темы; до двух опросов
   за слот, до семи за серию и до двух попыток на тему. Кворум — три содержательных
   ответа в одном вопросе. 28 дней начинаются только после подтверждённой Telegram
   отправки. Обычные опросы и существующее удаление сообщений работают как раньше.

## Аналитический контракт

`comparison-v1-draft` и старые шкалы сохранены без переосмысления. Новый
`comparison-v2` разрешает семнадцать явно определённых семейств. Это технический
словарь сравнения, не научная валидация предпочтений и не утверждение качества AI.
Интерес, удовольствие и правдоподобность не объединяются. Код строит точные варианты,
порядок и признаки содержательных ответов. «Не смотрел» и «Не могу оценить» не входят
в знаменатель содержательных долей, но исходные counts сохраняются.

Каждый вопрос сохраняет версии словаря и формулировки, TMDB ID, watch revision,
семейство, предмет, шкалу, контекст и ссылки на источники. Миграции 22–23 добавляют
immutable source/dossier/preparation/approval snapshots и рабочие checkpoints.
Сохранение готового ответа проверяет ревизию просмотра, отсутствие детей и версию
checkpoint; approval привязан к точному сохранённому набору. Отмена, отключение
подготовки и устаревшие ревизии освобождают очередь, не переписывая историю.

`ProjectResearch` — отдельная чистая проекция. Внутри просмотра выбирается первый
закрытый совместимый вопрос семейства с минимум тремя ответами, внутри фильма —
последний такой просмотр. Вклад каждого фильма одинаков. Повторный опрос не добавляет
ему веса. 1–2 ответа остаются provisional, несовместимые записи видны в диагностике.
Доступны канонические poll IDs и digest аналитических входов для воспроизводимого
анализа. Суммирование выполняется в стабильном порядке. Служебные поля доставки,
cleanup и повторов не меняют digest.
Старые v1-аспекты считаются отдельно. Корреляции между людьми не вычисляются:
персональные голоса и переписка не сохраняются.

В Telegram: `/movie_profile` → «Аспекты» → «Особенности фильмов». Раздел разбит на
страницы по три семейства. Карточка просмотра показывает адресные темы и покрытие.
JSON-экспорт включает источники, подготовку и approval; CSV — descriptor каждого ответа.
Миграция не пересчитывает старые результаты под новый смысл.

## Проверка перед включением

`cmd/research-eval` выполняет один этап вне Telegram, без миграций и без создания
опросов. В production БД пишет только стандартные счётчики API; всё остальное сохраняет
в новый файл с правами 0600. `--limit` ограничен 20, по умолчанию 16 оставляет четыре
вызова штатной работе. Один запуск допускает один фактический HTTP-запрос к AI.
`--movie ID --output sources.json` собирает материал; последующие запуски используют
`--input sources.json --output generated.json --provider groq --model openai/gpt-oss-120b`.
Рядом сохраняются только structured-ответ и безопасный HTTP status, без сырого envelope,
ключей и заголовков. Для следующего этапа передаётся предыдущий checkpoint.

Для честного сравнения конфигураций нужен один source checkpoint и разные выходные
файлы. Не сравнивать меняющиеся досье. Сохранять rejected результаты, отдельно оценивать
источники, нейтральность, точность шкал и читабельность. Начать с `shadow` в тестовом чате,
после приёмки разрешить `on` для новых просмотров. До этого готовность кода не означает
готовность выпуска. Этот этап выполняется без анонсов по поручению пользователя.

Для выпуска без сообщений коммит push содержит маркер `[skip announce]`: workflow
пропускает весь шаг публикации анонсов, включая старые ожидающие записи.
