# Пилот отбора кинофактов

Отдельный исследовательский стенд. Не меняет бота, его SQLite, расписания или Telegram. Python 3.10+ и стандартная библиотека; отдельные зависимости не нужны.

## Набор

`dataset.json`: 24 фиксированных непрерывных отрывка из разделов производства шести фильмов, четыре пакета по шесть кандидатов. Есть сложные/слабые материалы и примеры Vertigo, Daffy Duck, затопленной декорации. Это исходные цитаты, не 24 проверенных готовых факта.

На каждый отрывок сохраняются полный нормализованный абзац, его SHA256, версия Wikipedia, URL и атрибуция CC BY-SA 4.0. Текст очищен от маркеров сносок и нормализован по пробелам. Содержательную достоверность нужно проверять по статье и её ссылкам; наличие цитаты само по себе её не доказывает.

`capture.py` воспроизводит набор по явным якорям `source_specs.json`. Существующий набор не перезаписывает: после изменения страницы якорь может отсутствовать, захват завершится ошибкой. Для повторного эксперимента исходный набор сохраняем.

## Запуск

```sh
python3 experiments/facts/run.py validate
python3 -m unittest discover -s experiments/facts -p 'test_*.py'
# Ключ только через environment или --env-file, не аргументом CLI.
python3 experiments/facts/run.py run --provider gemini --model MODEL_ID \
  --out experiments/facts/results/pilot-gemini --max-requests 12 --limit 1
# Продолжение: те же параметры без --limit 1.
python3 experiments/facts/run.py report --out experiments/facts/results/pilot-gemini
```

MODEL_ID указывается явно; стенд не выбирает платную/резервную модель. Первой попыткой проверяем доступность. Одна модель и один провайдер на каталог; менять данные, промпты, timeout и общий лимит при resume нельзя. Новому провайдеру нужен отдельный каталог. Температура остаётся provider default во всех режимах, output limit одинаковый 1536. Между запросами пауза 30 секунд (CLI --interval, максимум 60); без параллельных запросов.

HTTP User-Agent совпадает с рабочим Go-клиентом: `Go-http-client/1.1`. Groq отвергает Python-urllib User-Agent с 403 ещё до обработки моделью; это проверено отдельным GET списка моделей. Изменения транспорта требуют отдельного прогона и сохраняются в manifest.

Максимум 12 сетевых попыток, включая HTTP errors, таймаут и процесс, упавший после резервирования. Ретраев/fallback нет. Первая ошибка останавливает запуск; очередной ручной resume переходит к следующему неиспытанному сочетанию, не повторяет ошибку. Ошибки остаются пробелами в сравнении и не превращаются в успешные результаты. Квоты API общие с ботом; не запускать в его рабочей БД и не рассчитывать на отдельную квоту провайдера.

## Режимы

- A: базовый инструктаж «занимательный факт о создании фильма».
- B: неожиданность и необычные предметы/случайности/хитрости.
- C: конкретная законченная история с достаточным контекстом.

Это сравнение критериев отбора на фиксированных цитатах. A не является точным воспроизведением production: там другой вход, переписывание и второй редакторский запрос. Формат ответа одинаковый, но на этом этапе мы намеренно не генерируем готовые Telegram-посты. Модель может отказаться от всего пакета.

`attempts.jsonl` резервируется до POST; `results.jsonl` содержит только разрешённые поля результата/статуса/счётчиков токенов. `manifest.json` фиксирует хеши данных/промптов и модель. Не сохраняются ключи, запросы с заголовками и тела upstream ошибок. Одновременные процессы защищены lock. Каталоги результатов исключены из Git.

## Независимая оценка

Открыть `compare.html`: критерии отбора скрыты, видно историю и исходную цитату. Сравнивать варианты одного batch. Режимы раскрывает отдельный `answer-key.json`; до оценки его не смотреть. Метки стабильны при resume. Рationale модели не показывается, чтобы не убеждать оценщика.

Оценки можно выбрать прямо в HTML: они сохраняются в localStorage только этого браузера, кнопка «Скачать оценки» экспортирует `ratings.json`. Альтернатива: скопировать `ratings-template.json` в `ratings.json` и заполнить interest/clarity/share 0–2, supported true/false, comment. Одинаковые истории под разными метками — допустимый результат, не независимые подтверждения качества. Можно забраковать все варианты. HTML не отправляет оценки на сервер.

Одной генерации на сочетание недостаточно для вывода о победителе. После первого пилота: независимая оценка, новые материалы (holdout), затем повторный прогон. Пересказ compact/story сравниваем после отбора, одинаковые источники и одна модель. Внедрение/анонс/деплой только после этого, в отдельной задаче.

## Оценки первого пилота

```sh
python3 experiments/facts/analyze.py --ratings ~/Downloads/ratings.json \
  --out experiments/facts/results/pilot-2026-10-08/groq-compatible
```

Стенд проверяет ID, пакет, отсутствие дубликатов, полноту строк и типы оценок. Пустые оценки не превращаются в нули; NONE исключается из оценок историй. Исходный файл копируется в новый каталог `evaluation-HASH` рядом с результатами, без перезаписи скачанного файла. Отдельный JSON содержит сопоставление с режимами и ограничения сравнения. Повторный импорт того же файла намеренно не перезаписывает оценку.

Первый оценщик заполнил интерес/понятность/желание отправить для всех девяти историй: пять получили понятность 0, четыре — ненулевое желание отправить (два — максимальную оценку). Вариант NONE не оценён; для одной истории не указан supported. A получил более высокие оценки, но это не доказательство качества критерия: тексты содержали подмены имён и событий, были повторы эпизодов, по одному ответу B и C не прошло проверку формата. Оценка supported не отменяет найденных расхождений с источником.

## Пересказ одной и той же истории

`rewrite-dataset.json` — отдельный набор из трёх эпизодов, заинтересовавших оценщика. Оригинальные 24 цитаты не меняются. Теперь используются полные сохранённые абзацы с вручную подготовленными пояснениями имён, смысла эпизода и рисков искажения. Это дополнительный контекст, который в дальнейшем тоже потребуется получать и проверять; пилот не измеряет готовность автоматической production-системы. [UCLA — университет в Лос-Анджелесе](https://www.ucla.edu/about); пояснение снимает замечание о непонятной аббревиатуре.

`rewrite.py`: компактный ориентир 35–60 слов и развёрнутый 80–130 слов, с абзацами и конкретным событием в начале. Объём — пожелание; если информации мало, запрещено добавлять выдумки и повторы ради числа слов. Поле hook теперь содержит готовый текст. JSON-схема, модель, лимит output 1536, транспорт и temperature одинаковы. Поменялись и объём источника, и общий промпт: сравнивать с первым пилотом как чистый эффект длины нельзя. Внутри пары источник и пояснения одинаковы.

```sh
python3 experiments/facts/rewrite.py validate
python3 experiments/facts/rewrite.py run --provider groq --model MODEL_ID \
  --out experiments/facts/results/rewrite-groq --env-file /path/to/private.env --limit 1
# Продолжение с теми же аргументами, без --limit 1: максимум 6 POST всего.
python3 experiments/facts/rewrite.py report --out experiments/facts/results/rewrite-groq
```

Ключи остаются в исходном окружении; на компьютере нужен только каталог результатов. Бюджет нового прогона — шесть попыток, включая ошибки; перенос ошибок в другой каталог для обхода лимита недопустим. Файлы оценок, цитаты и ответы раздельны. После генерации вручную проверяем соответствие имён и утверждений сохранённому источнику; это проверка пересказа, а не независимое подтверждение самого события. Затем человеческая оценка в новом compare.html. Плохие ответы сохраняются в журнале, а не скрываются за повторным запросом. Новые источники для holdout выбираются только после этой оценки.


Второй пилот (2026-10-08) исчерпал лимит шести попыток: пять формально валидных JSON-ответов, один HTTP 429. После паузы остальные запросы прошли. Все пять пересказов отклонены при ручном сопоставлении с источником: подмена имени, неподтверждённые подробности, mixed-script, оборванная фраза и неестественный язык. Это итог данного небольшого прогона, не оценка модели во всех задачах. Ни compact, ни story не прошёл смысловую проверку; пригодность длины по нему не доказана. Источники, ответы и semantic-audit сохранены отдельно. Следующим экспериментом следует проверить языковую/смысловую надёжность модели на том же материале; holdout и production-изменения пока не начинались.


Оценки пересказов импортируются отдельно:

```sh
python3 experiments/facts/analyze.py --phase rewrite \
  --ratings "$HOME/Downloads/ratings (1).json" \
  --out experiments/facts/results/rewrite-2026-10-08/rewrite-groq
```

Для этой фазы анализатор сравнивает только полные compact/story пары одного эпизода, а не общие средние разного набора историй. Пользователь оценил все пять текстов: Хенриксен 0/0/0 в обоих форматах; финал «Терминатора» интереснее в story (2 против 1), но понятность и желание отправить одинаковые (1). Про коляски есть только compact 1/1/1. На двух парах преимущество развёрнутого формата по понятности не показано. supported — субъективная оценка; найденные расхождения с источниками сохраняются в отдельном semantic-audit. Следующий этап — проверка моделей на неизменных источниках, прежде чем выбирать длину или идти на holdout.


## Цикл с редактором

`editor_cycle.py` выполняет до трёх draft и до трёх repair POST в разных папках одного цикла. Каждый эпизод получает максимум одну исправленную версию; HTTP-ошибки тоже расходуют бюджет. Source corpus, input hash, provider/model и reasoning_effort фиксируются, контекст и цитаты при repair менять нельзя. previous_draft должен совпасть с реальным сохранённым ответом; parent_draft_dataset_sha256 — с manifest исходного прогона. Ключи, upstream bodies и reasoning не сохраняются.

Редактор здесь — Codex в текущем чате. Он вручную сопоставляет ответы с сохранёнными источниками и пишет feedback, после чего отдельный API-запрос генерирует правку. Это эксперимент, а не встроенный production-проверяющий. Оценщик видел предыдущие пользовательские оценки, поэтому оценка не слепая. Наличие evidence в JSON не отменяет редакторской проверки.

```sh
python3 experiments/facts/editor_cycle.py --stage draft \
  --out experiments/facts/results/editor-oss20 --model openai/gpt-oss-20b \
  --env-file /path/to/private.env --limit 1
# Resume с теми же параметрами, без --limit 1. Draft cap = 3.
# После отдельной записи редакторских замечаний и repair-dataset.json:
python3 experiments/facts/editor_cycle.py --stage repair \
  --dataset experiments/facts/results/editor-oss20/repair-dataset.json \
  --out experiments/facts/results/editor-oss20 --model openai/gpt-oss-20b \
  --env-file /path/to/private.env
```

GPT-OSS требует [reasoning_effort low/medium/high](https://console.groq.com/docs/reasoning), поэтому новый цикл использует low, а исходный Qwen — none. [Обе модели поддерживают strict JSON](https://console.groq.com/docs/structured-outputs). Output cap 1536 и исходный промпт/корпус сохранены. Это сравнение двух конфигураций модели, а не измерение эффекта только одного параметра. Модель указана в [таблице free-plan лимитов](https://console.groq.com/docs/rate-limits); billing/account settings не меняются, отсутствие списаний стенд сам не проверяет.


Результат цикла 2026-10-08: 3 draft + 3 repair HTTP/JSON успешны, но все шесть пересказов отклонены по смыслу/языку. Редакторские замечания уменьшили количество ошибок, но модель оставила и добавила неподтверждённые утверждения. Поэтому Codex отдельно переписал три примера (`edited-facts.json`): источник и claim→evidence сохранены, provenance ясно отделяет эти редакции от raw provider output. `edited.html` показывает только редакторские примеры, сырые результаты доступны в draft/repair. Это прототип процесса, не работающий production-судья и не доказательство истинности исходных Wikipedia-историй. Следующий шаг перед внедрением — проверить автоматическую сильную редакцию и критерии на новых материалах; удерживать отдельно данные генерации, review, repair и человеческих оценок.


## Другие источники и русский вход

`source-models-dataset.json` содержит четыре новых фиксированных случая: русские фрагменты Wikipedia о дыне в «Психо» и LED-кубе в «Гравитации», а также близкие эпизоды BFI и Academy. Это не чистый тест языка: у разных статей разные детали (например, сорт дыни и размеры куба). Новый короткий промпт не требует минимального объёма и соседних абзацев.

Русские цитаты проверены по загруженному HTML Wikipedia, закреплены revision 154897465/154441189. BFI и Academy проверены через web.run, сохранены только короткие цитаты до 25 слов и собственный краткий пересказ поддерживающего контекста. Локальная загрузка BFI вернула 403; автоматический сбор из этого источника не доказан, обход блокировки не выполнялся. BFI, AFI и Academy полезны как редакционные/производственные источники, но не считаются CC BY-SA. Старый загрузчик по умолчанию принимает только en.wikipedia.org; расширенный профиль применяется только явно в этом эксперименте.

Конфигурации: GPT-OSS 120B low, Qwen low, Gemini 3.8 Flash. На каждую максимум четыре попытки, до 12 всего; ошибки считаются и останавливают часть провайдера. Нет автоматического fallback или повторов. Корпус и промпт одинаковые для моделей, manifests раздельные; output cap 1536. В новых ответах записывается публичное имя модели из ответа провайдера, если оно есть. Оно не восстанавливается задним числом для прежних ответов.

```sh
python3 experiments/facts/source_models.py --configuration oss120 \
  --out experiments/facts/results/sources-models-v1 --env-file /path/to/private.env --limit 1
# Продолжение: убрать --limit 1. Другие configurations: qwen-low, gemini.
```

Ссылки: [BFI о звуке в Psycho](https://www.bfi.org.uk/interviews/psycho-shower-scene-alfred-hitchcock), [Academy о Gravity](https://www.oscars.org/events/deconstructing-gravity), [AFI Catalog о Jaws](https://catalog.afi.com/Catalog/moviedetails/55193). AFI изучен, но в этот фиксированный прогон не включён. Результаты и редакторская оценка — разные файлы. Прототип русского extractive-варианта копирует только уже понятный законченный фрагмент, не дописывает детали модели; готовность такого отбора на массовом корпусе ещё не проверена.


Итог этого пилота: 10/12 попыток, 9 текстов и один 503 Gemini; остальные два его случая не запускались. Проверка Codex: 2 ready, 3 needs_edit, 4 reject. Два ready пришли на русских фрагментах, но RU Psycho вызвал выдумки режиссёров у Groq-моделей, поэтому язык не гарантирует точность. В EN случаях некоторые ошибки были небольшими и исправимыми; объявлять русский вход победителем на двух фильмах нельзя. Native baseline для Psycho воспроизводит законченный исходный фрагмент после удаления первого союза и изменения заглавной буквы; это одна проверенная демонстрация, не готовый автоматический extractive pipeline. Корпус/ответы/редакторские оценки сохранены отдельно, источник не заменён оценкой модели. Для следующего этапа рекомендуемый эксперимент — RU-first с необязательным пересказом и новыми фильмами.


## Русский holdout без пересказа · 2026-10-09

Десять новых заранее заданных фильмов. `holdout_capture.py` собирает целые абзацы производственных разделов, 20–140 слов, максимум 12 равномерно распределённых подходящих абзацев на фильм. Интерес не используется при сборе. Первый корпус сохранён как `ru-holdout-dataset.json`: 69 абзацев, у двух фильмов материал не распознан. Исправлены заголовок «Работа над фильмом» и неоднозначный адрес «Сияния». Второй неизменный корпус `ru-holdout-v2-dataset.json` содержит 88 абзацев.

Для API до редакторской оценки механически выбраны по четыре абзаца на фильм: `ru-holdout-selection-dataset.json`, 40 кандидатов, SHA256 `4697607f99ad0a7f6df2471b08ad903486406c9fb55b8c4196f0ae66690eb29d`. Это ограниченная выборка; отсутствие хорошего абзаца среди четырёх не означает отсутствие хороших материалов о фильме вообще. Все три корпуса сохраняются отдельно, parent hash связывает API-вход со вторым корпусом.

`extractive.py` запрашивает строго `{selected_id}` или NONE. Никаких hook/названий/пересказов модель не пишет. Адаптер копирует точный абзац в прежнюю структуру стенда; свободный текст или посторонний ID отвергаются. `run.request` принимает явную response_schema, старый формат по умолчанию сохранён. До четырёх попыток на Gemini 3.8 Flash и GPT-OSS 120B low, максимум восемь; manifest/budget/ошибки остаются неизменными, ожидание между запросами 60 секунд, без автоматического retry/fallback.

```sh
python3 experiments/facts/extractive.py --configuration gemini \
  --dataset experiments/facts/ru-holdout-selection-dataset.json \
  --out /path/to/private-results --env-file /path/to/private.env
# Вторая независимая конфигурация: oss120, ещё максимум четыре попытки.
python3 experiments/facts/holdout_report.py \
  --dataset experiments/facts/ru-holdout-selection-dataset.json \
  --root experiments/facts/results/holdout-2026-10-09
```

В текущем прогоне выполнено 6/8 попыток: Gemini один успешный выбор и затем 503; GPT-OSS четыре успешных выбора. Ошибку не повторяли и оставшиеся два Gemini-запроса не выполняли. 13602 reported tokens успешных ответов; расход ошибочного запроса неизвестен. Все пять показанных абзацев побайтно совпадают с исходными excerpt.

До просмотра выбранных моделями ID Codex отдельно оценил все 40 кандидатов (`candidate-review.json`): interest/clarity 0–2, пригодность требует 2/2 и отсутствия крупного спойлера финала. ## TMDB → Wikidata → русские источники · 2026-10-09

Пользователь одобрил следующий эксперимент с 50–100 фильмами. `catalog_probe.py` собрал 70 уникальных ID из семи групп по десять: 1960–1979, 1980–1999, 2000–2009, 2010–2019, 2020–2026, русскоязычное кино до 2020 и недельные тренды. Seed=20261009, страницы Discover от 1 до 3 выбираются до сети. Sort popularity.desc, минимум 200 голосов (50 у русскоязычной группы), без adult/video и будущих дат. Внутри группы seeded shuffle, мягкий лимит три фильма на первый жанр с последующим заполнением; глобальная дедупликация ID. Это не равномерная выборка всего кино.

[TMDB Discover](https://developer.themoviedb.org/reference/discover-movie) и [External IDs](https://developer.themoviedb.org/reference/movie-external-ids) получены на сервере существующим TMDB_API_TOKEN; ключ читается только там из runtime.env и не попадает в результаты/логи. Доступность Wikidata/русской Wikipedia измерена в локальном стенде. Отдельный один GET русской статьи с сервера сохранён как server-access.json; он не доказывает доступность всех источников или работу production-бота.

Бюджеты: до 7 catalog GET, 70 external ID GET, 70 Wikidata GET, 70 Wikipedia GET. Автоматических retry нет. Попытка записывается до сети; ошибка или неопределённое завершение не повторяются при resume. Фазы фиксируют входные hashes, общий protocol содержит hash скрипта; файловый lock защищает от двух одновременных запусков. `.env`, headers и upstream error bodies не сохраняются. Redirects запрещены. Сохраняются исходные публичные метаданные, выбранные абзацы и hashes; полные HTML-статьи не сохраняются.

Связь требует TMDB QID, обратного P4947 с ровно одним соответствующим ID, непротиворечивого IMDb при наличии, совпадения названия с RU/EN label или alias, года в пределах одного от заявленного в TMDB. Если статья найдена, её собственный wgWikibaseItemId тоже должен совпасть. Похожий заголовок, ремейк или перевод не принимается автоматически. [Wikidata P4947](https://www.wikidata.org/wiki/Property:P4947) — идентификатор TMDB. Наличие этих метаданных не доказывает правдивость каждой истории в статье.

```sh
# Только на сервере, существующий ключ остаётся там:
python3 catalog_probe.py --phase catalog --out tmdb-ru-v1 --env-file /path/to/private.env
python3 catalog_probe.py --phase external --out tmdb-ru-v1 --env-file /path/to/private.env
# Публичные результаты можно перенести в локальный стенд; не переносить ключ:
python3 experiments/facts/catalog_probe.py --phase wikidata --out /path/to/tmdb-ru-v1
python3 experiments/facts/catalog_probe.py --phase wikipedia --out /path/to/tmdb-ru-v1
python3 experiments/facts/catalog_report.py --root /path/to/tmdb-ru-v1
```

Основной прогон: 213 GET (7+70+70+66), все HTTP успешны, без повторов/AI. Один дополнительный server-source smoke укладывается в общий предел Wikipedia ≤70. У всех 70 есть TMDB QID, у 69 пройдены строгие имя/год/ID, 66 имеют подтверждённую русскую статью. Три фильма без RU sitelink. Один остановлен из-за разных переводов «Бесконечный замок»/«Бесконечная крепость»: сохранён как needs_identity_review, не объявлен неправильным фильмом. Из 66 статей whitelist разделов и фильтр целых абзацев 20–140 слов дали материал в 53. Всего 359 подходящих абзацев, для audit сохранено до четырёх равномерных на фильм — 170. 17 первых жанров; у фильма может быть несколько жанров.

Заранее зафиксированы 14 фильмов, первые два после seeded shuffle каждой группы, без замены пропусков. Для основной субъективной проверки Codex берутся первый/последний из сохранённых абзацев. Для трёх выбранных фильмов подходящих абзацев не получено; ещё два фильма дают только по одному подходящему абзацу. Итого 20 текстов, три пригодны без пересказа из двух фильмов. Это не пользовательские оценки и не независимая фактологическая проверка.

После первичной оценки выполнена отдельная exploratory диагностика: средние два абзаца первых четырёх ранее выбранных фильмов с четырьмя сохранёнными абзацами, восемь всего. Один пригоден без пересказа. История с необналиченным чеком Кинга найдена внутри абзаца со спойлером и недостающим контекстом — кандидат на отдельный эпизод, а не на целый пост. Диагностические оценки отдельно от исходной выборки, не объединяются в один показатель качества.

Вывод: TMDB годится как пополняемый каталог кандидатов, но популярность/наличие статьи не заменяет отбор истории. Полезные эпизоды нужно выделять с достаточным контекстом, проверять смысл/понятность и складывать в готовый пул. Для 13 статей whitelist h2 не выделил производственных абзацев; это ограничение сборщика, а не доказательство отсутствия информации. Новинки часто дают кастинг/даты без яркой истории, но вывод ограничен небольшим editorial sample.
